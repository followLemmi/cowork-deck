# cowork-deck — внешний терминал (дополнение к спецификации)

Дата: 2026-07-22
Статус: согласовано, готово к плану

## Изменение замысла

Пользователю не нравится встроенный отрисовщик терминала (xterm.js). Переходим на запуск
каждой сессии во **внешнем терминале-приложении** на выбор (Ghostty и т.п.). Встроенный
xterm убираем.

Определение состояния (перехватчики Claude Code → докладчик → локальный слушатель) от
отрисовки не зависит, поэтому метки состояния и системные уведомления сохраняются.

## Как задаётся терминал

Глобальная настройка — **редактируемый шаблон команды** (строка-приставка). Строка
разбивается на аргументы с учётом кавычек (как в оболочке).

**Пустой шаблон = системный терминал по умолчанию** (автоопределение). Поле можно
переопределить своей командой (например `ghostty -e`, `wezterm start --`).

Автоопределение по системам:
- **Linux:** переменная `$TERMINAL` (если задана) → иначе `x-terminal-emulator -e`
  (штатный механизм «терминала по умолчанию» в Debian/Ubuntu) → иначе первый найденный
  из известного списка (ghostty, wezterm, kitty, alacritty, gnome-terminal, konsole,
  xterm) со своим корректным флагом запуска команды.
- **Windows:** `wt` (Windows Terminal), если установлен; иначе `cmd /c start`.
- **macOS:** запуск команды в терминале по умолчанию через `open` требует скрипта-обёртки
  и не ложится в простую модель «приставка + аргументы». Делается по мере возможности;
  при неудаче пользователь задаёт свой шаблон. Проверяется только на Linux.

## Запуск сессии

1. Формируется JSON перехватчиков (как раньше, `build_settings_json`) и пишется во
   **временный файл** `<tmp>/coworkdeck-<session>.json` (надёжнее встроенного JSON при
   прохождении через запуск терминала).
2. Итоговый вызов: `<приставка> <claude> --settings <файл> [текст задания]`,
   рабочая папка = путь пространства. Процесс терминала запускается открепл ённо; его
   дескриптор сохраняется в реестре для гашения при закрытии окна.
3. Метка сессии сначала «готов», далее меняется по событиям перехватчиков.

## Окно-пульт

- Область плиток заменяется **списком карточек сессий**: имя + метка состояния
  (готов/работает/ждёт ввода/завершён/ошибка) + кнопка «убрать».
- Кнопки сценариев, переключатель пространств, «+ сессия», уведомления — как есть.
- Добавляется поле настройки «команда терминала».

## Обработка завершения и закрытия

- Завершение сессии определяется по перехватчику `SessionEnd` → метка «завершён».
- При закрытии окна пульта приложение гасит процессы терминалов, которые запускало
  (реестр дескрипторов). **Ограничение:** некоторые терминалы работают через единый
  фоновый процесс (single-instance), поэтому запущенный процесс может завершиться сразу,
  а окном управляет фоновый демон — в этом случае гашение по дескриптору не закроет окно.
  Это честно документируется; правило «сессии завершаются вместе с окном» соблюдается по
  мере возможности.

## Что убираем / меняем в коде

- Убираем: xterm-панель (`src/terminal.ts`), команды `write_session`/`resize_session`
  (ввод идёт напрямую во внешний терминал), поток вывода `session://output`.
- Оставляем и переиспользуем: `build_settings_json`, локальный слушатель, модель
  состояний, хранилище (добавляем в него настройки), уведомления.
- `PtyManager` для встроенного режима больше не нужен для запуска сессий; заменяется
  реестром внешних процессов-терминалов.

## Границы

- Один режим — внешний терминал (встроенного больше нет).
- Остальные сквозные требования прежние (минимум ресурсов, кросс-платформенность,
  пространства по проектам, только 127.0.0.1, один пользователь).
