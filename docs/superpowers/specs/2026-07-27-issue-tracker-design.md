# cowork-deck — встроенный трекер задач — Design Spec

**Дата:** 2026-07-27
**Ветка:** worktree-feat-issue-tracker
**Контекст:** в деке есть воркспейсы, сценарии, расписания и ручной прогон сценария (⏰). Состояние сессий приходит от Claude Code через хуки: хелпер-бинарь `src-tauri/src/bin/cowork_report.rs` пишет строку JSON в TCP-листенер (`listener.rs`) на `127.0.0.1:<port>`, зная свой `session` id. Roadmap содержит «Project memory» и «Agent teams»; трекер задач лежит на стыке этих пунктов и должен их не заблокировать.

## Цель

Дать возможность зафиксировать задачу или баг **не теряя контекст**: ни своего (не переключаясь в браузер посреди работы), ни агентского (сессия оформляет побочную находку тикетом вместо того, чтобы расползаться по скоупу или молча забыть).

Полезность фичи сосредоточена в одном месте: **агент как источник задач**. Всё остальное — обслуживание этого.

## Границы (scope)

**Входит:**
- Модель карточки и файловый провайдер (`.cowork/tasks/` или произвольный каталог).
- Трейт `TaskProvider` + `ProviderCapabilities` — шов для будущих GitHub/Jira.
- Конфигурация трекера **на воркспейс**, включая выбор места хранения.
- Вид «Доска» в деке + счётчик открытых задач в сайдбаре.
- Захват карточки человеком (модалка по хоткею) и сессией (CLI `cowork_task`).
- ▶ запуск сессии из карточки; выводимое состояние «в работе»; явное закрытие.
- Watcher каталога с fallback на опрос.

**НЕ входит:**
- **Провайдеры GitHub Issues и Jira** — отдельные спеки поверх готового трейта. Здесь только шов.
- **Хранение секретов / keychain** — приезжает вместе с первым сетевым провайдером.
- **Канбан-процесс** (промежуточные стадии вроде `todo` / `review`) **и произвольные статусы.** Только `open → done`; «в работе» выводится, а не хранится. Две колонки на доске — это отображение этих двух состояний, а не доска процесса.
- **Автоподъём сессии по новой задаче.** Запуск только по кнопке — иначе опечатка в карточке стоит сожжённых токенов.
- **Синхронизация между хранилищами**, слияние бэклогов, разрешение конфликтов между провайдерами.
- **Приоритеты, лейблы, спринты, назначение исполнителя, комментарии.** Инбокс на одного человека — это список.
- **Автокоммиты файлов задач приложением.** См. решение 4.
- **Шаблон имени файла в настройках.** См. решение 6.

## Ключевые решения

1. **Файлы — источник правды, за портом.** Карточки живут в markdown-файлах, но UI никогда не знает про файлы: только `list` / `create` / `resolve` / `capabilities` через IPC. Трейт `TaskProvider` — единственный шов, куда позже садятся GitHub и Jira; файловый провайдер не особый случай, а первая реализация.

2. **Место хранения выбирает пользователь, на каждый воркспейс.** Либо `.cowork/tasks/` внутри проекта, либо произвольный каталог — тогда пользователь может выделить под бэклог отдельный репозиторий, положить его в Obsidian-волт или в синхронизируемую папку. `FsTaskProvider` получает корень и не интересуется его происхождением.

3. **Markdown + frontmatter, а не JSON.** Формат читаем человеком, редактируем в любом редакторе и нативен для Obsidian (вики-ссылки и Dataview заработают сами). Он же делает агента полноправным читателем бэклога без единого нового тула.

4. **Правило git привязано к месту, а не к фиче.** `kind: project` → файлы **трекаются обычным образом**: без `.gitignore`, без автокоммитов от приложения. Задачи — часть проекта, коммитит их тот, кто и так коммитит код; побочный эффект (сессия с `git add -A` утащит файл задачи в свой коммит) принимаем и документируем. Внешний каталог — не наша забота вообще.
   *Рассмотрено и отклонено:* `.gitignore` + выборочный `git add -f`. `.gitignore` не действует на уже отслеживаемые файлы, поэтому защита исчезает после первого же шаринга — это отложенный вариант «трекаем», а не третье состояние. `git update-index --skip-worktree` отклонён как локальный-только и слетающий на checkout/pull. Автокоммиты приложением отклонены: это новая ответственность «трекер пишет в git» с guard'ами на rebase/detached HEAD, и лекарство дороже болезни.

5. **ULID вместо инкрементных номеров.** Две сессии, оформляющие тикет одновременно, не столкнутся, а лексикографическая сортировка ULID сохраняет порядок по времени. Инкрементные номера потребовали бы блокировки каталога.

6. **`id` дублируется внутри файла, разрешение — по `id`, не по пути.** В волте заметку переименуют в человеческое имя в первый же день, и это законная операция. `resolve` ищет файл в индексе по `id`. Отсюда же отказ от настройки «шаблон имени файла»: `<ulid>-<slug>.md` нужен только при создании, дальше переименовывай как хочешь.

7. **`project:` пишется всегда, и это имя воркспейса.** На общем корне (три воркспейса → одна папка волта) карточка иначе не знает, к какому проекту относится, а ▶ обязан запустить сессию в правильном каталоге. При персональном корне поле избыточно и безвредно.
   Именно имя, а не локальный id и не путь: бэклог в волте или в отдельном репозитории переезжает между машинами, где локальный id ничего не значит. Плата за это осознанная и её надо знать: **переименование воркспейса разрывает связь** — карточки остаются в файлах, но фильтр доски их не покажет, пока имя не совпадёт. Автомиграцию не делаем (пришлось бы переписывать чужие файлы, возможно в общем репозитории); вместо этого доска показывает «N карточек с другими `project:`» со списком имён, чтобы промах был виден, а не выглядел потерей данных.

8. **Карточка — это файл с валидными `id` и `title`; остальное игнорируется молча.** Направить корень на папку с сотней обычных заметок — нормальный сценарий, и он не должен давать сотню ошибок. Скан не рекурсивный: предсказуемо и не прочёсывает весь волт.

9. **`status: done` полем, а не переносом в `done/`.** Перенос ломает связь `id`↔путь и даёт rename-шум в диффе; поле проще, а колонка «done» работает одинаково.

10. **Захват сессией — через env + CLI, а не через TCP-канал.** Дека сама спавнит PTY, поэтому подставляет в окружение путь к корню, имя проекта и путь к бинарю. Агент делает одну команду; TCP-листенер не задействован, так что захват работает, даже если окно занято или листенер отвалился. Бинарь (а не «пусть агент сам пишет markdown») гарантирует корректный ULID и frontmatter.

11. **«В работе» выводится из живых сессий, а не хранится.** Связка `task_id → session_id` живёт на записи сессии в store. Сессия умерла — карточка молча вернулась в `open`; «зависших in progress» не бывает по конструкции, и чистить ничего при старте не надо.

12. **Закрытие только явное.** Ты жмёшь ✓ либо сессия делает `cowork_task done <id>`. Завершение сессии карточку **не** закрывает: «сессия закончилась» и «задача сделана» — разные события, склеивать их значит врать в бэклоге.

13. **Провайдер объявляет возможности, UI деградирует.** `ProviderCapabilities` (можно ли создавать, можно ли закрывать, какие статусы) — потому что `open → done` не отображается один-в-один в Jira transitions. UI скрывает недоступное действие, а не падает; тот же принцип, что у терминала без хуков.

## Модель данных

### Карточка — `<root>/<ulid>-<slug>.md`

```markdown
---
id: 01K1B7QW9XZ3M4N5P6R7S8T9V0
title: Пилюля мигает при переключении воркспейса
kind: bug                       # bug | task | idea
status: open                    # open | done
project: cowork-deck
created: 2026-07-27T13:20:11Z
resolved: 2026-07-27T15:02:44Z   # только при status: done
origin: session                 # human | session
session: a3f1c2                 # только при origin: session
---

Репро: три воркспейса, Cmd+2 → пилюля дёргается на ~200мс.
Похоже на пересоздание элемента в `pill.ts` вместо обновления текста.
```

Обязательные поля: `id`, `title`, `status`, `project`, `created`, `origin`. `kind` по умолчанию `task`. `resolved` нужен для сортировки колонки done. `origin`/`session` — чтобы на доске было видно, что тикет прилетел от бота, а не от тебя: это и делает фичу не страшной.

### Конфиг трекера — в store деки, на воркспейс

```jsonc
{
  "tracker": {
    "providers": [
      { "type": "fs", "root": { "kind": "project" } }
      // или: { "type": "fs", "root": { "kind": "path", "path": "/home/…/lemmi-vault/Tasks" } }
    ]
  }
}
```

`providers` — список, а не одиночное поле: GitHub приедет добавлением элемента, а не переписыванием схемы. Токенов в этом конфиге нет и не будет — они пойдут в системный keychain вместе со спекой сетевого провайдера. Воркспейс без `tracker` — легальное состояние: доска показывает пустое состояние с «настроить».

## Компоненты

### Rust — новый модуль `src-tauri/src/tasks/`

| Файл | Обязанность | Зависит от |
|---|---|---|
| `tasks/model.rs` | `Task`, `TaskDraft`, `TaskId`, `TaskStatus`, `TaskKind`, `TaskOrigin`, `TaskError` — чистые типы, никакого I/O | — |
| `tasks/provider.rs` | Трейт `TaskProvider` + `ProviderCapabilities` | model |
| `tasks/frontmatter.rs` | Парсинг и сериализация frontmatter; чистые функции над строкой | model |
| `tasks/fs.rs` | `FsTaskProvider`: скан каталога, запись temp+rename, реализация трейта | model, provider, frontmatter |
| ~~`tasks/index.rs`~~ | **Не реализовано** — см. отклонение от спеки ниже | — |
| `tasks/watch.rs` | Тонкая обвязка `notify` + дебаунс; уведомляет фронтенд, что каталог изменился | — |

**Отклонение от спеки:** `tasks/index.rs` не строился. `fs.rs` пересканирует каталог на каждый вызов
(`list`/`create`/`resolve`), что при ожидаемом масштабе (карточки одного пространства, файловая
система, не тысячи записей) ведёт себя эквивалентно индексу, но проще и без отдельного состояния,
которое нужно держать согласованным с диском. Поведение, которое индекс должен был гарантировать —
`resolve` находит карточку по `id` даже после того, как файл переименовали вручную (Obsidian это
делает при переименовании заметки в Finder/дереве) — уже покрыто тестом
`fs::tests::resolve_finds_the_card_after_the_file_was_renamed` и проходит без индекса. Если каталог
вырастет настолько, что полный скан на каждый вызов станет заметен, тогда и стоит строить индекс —
не раньше.

```rust
pub trait TaskProvider {
    fn capabilities(&self) -> ProviderCapabilities;
    fn list(&self, project: &str) -> Result<Vec<Task>, TaskError>;
    fn create(&self, draft: TaskDraft) -> Result<Task, TaskError>;
    fn resolve(&self, id: &TaskId) -> Result<Task, TaskError>;
}
```

Трейт узкий намеренно. Всё, чего провайдер не умеет, он **объявляет**, а не имитирует.

**Чего в `tasks/` нет и не должно появиться:** ничего про сессии, PTY и промпты. Провайдер не знает, что кто-то умеет запускать терминалы.

### Rust — новый бинарь `src-tauri/src/bin/cowork_task.rs`

Сосед существующего `cowork_report`. Читает окружение, пишет файл напрямую — без сети.

**Он обязан переиспользовать `tasks::frontmatter` и `tasks::fs`, а не иметь свою реализацию формата** — иначе у карточки появятся два писателя с расходящимися представлениями о ней, и это разойдётся при первой же правке модели. Существующий `cowork_report` самодостаточен и ничего из крейта не импортирует, поэтому здесь потребуется **lib-таргет** (`src-tauri/src/lib.rs`), экспонирующий модуль `tasks`, — иначе бинарь не сможет линковать этот код. Это единственное структурное изменение в крейте, которого не требовала ни одна прошлая фича, и его надо сделать сразу: разъехавшийся формат потом стоит дороже.

```bash
"$COWORK_TASK_BIN" new --kind bug --title "Пилюля мигает при переключении" <<'EOF'
Репро: три воркспейса, Cmd+2 → дёргается ~200мс.
EOF

"$COWORK_TASK_BIN" done 01K1B7QW9XZ3M4N5P6R7S8T9V0
```

Переменные, которые дека подставляет при спавне PTY (правка `pty.rs`):

```
COWORK_TASKS_DIR=/home/…/lemmi-vault/Tasks
COWORK_PROJECT=cowork-deck
COWORK_TASK_BIN=/opt/cowork-deck/bin/cowork_task
```

Читать бэклог агент может обычными тулами (`ls "$COWORK_TASKS_DIR"`, grep по нему) — обёртка для чтения не нужна. Навык/слеш-команда описывает агенту конвенцию: «нашёл побочную проблему — оформи тикет и продолжай свою задачу».

### Rust — IPC (`commands.rs`)

`tasks_list(workspace_id)`, `tasks_create(workspace_id, draft)`, `tasks_resolve(workspace_id, id)`, `tasks_capabilities(workspace_id)`. События в UI: `tasks://changed` (с id воркспейса) от watcher.

### Frontend

| Файл | Изменение |
|---|---|
| `src/tasks.ts` (новый) | Состояние доски, рендер, фильтрация/сортировка. Чистые `taskPrompt(task)` и `derivedStatus(task, sessions)` |
| `src/main.ts` (правка) | Переключатель «Терминалы / Доска» в шапке деки; проводка `tasks://changed` |
| `src/workspaces.ts` (правка) | Счётчик открытых задач у воркспейса в сайдбаре |
| `src/forms.ts` / `src/modal.ts` (переиспользование) | Модалка захвата: `title`, `kind`, тело |
| `src/palette.ts` (правка) | Пункты «Новая задача» и «Открыть доску» |
| `src/styles.css` (правка) | Стили доски и бейджей |

Хоткей захвата — `Cmd/Ctrl+Shift+T`; конкретная комбинация проверяется на коллизии с readline внутри терминала на Linux/Windows (та же оговорка, что в roadmap про `Ctrl+Shift`). Пункт в палитре есть независимо от хоткея.

**Запуск сессии не живёт в `tasks.ts`:** ▶ строит промпт чистым `taskPrompt(task)`, резолвит воркспейс из `project:` карточки и отдаёт управление существующей машинерии старта — тому же пути, что использует ⏰ run-now.

## Потоки

```
   хоткей ─┐                              ┌─→ индекс в памяти ─→ доска
           ├─→ FsTaskProvider ─→ файл ─→ watcher ─┤
cowork_task ┘   (temp + rename)                   └─→ бейдж-счётчик в сайдбаре

   ▶ ─→ taskPrompt(task) ─→ старт сессии (воркспейс из project:) ─→ связка на записи сессии
                                                                        └─→ «в работе» на доске
```

**Захват тобой:** хоткей → модалка → `tasks_create` → файл → watcher → доска. Воркспейс активный.

**Захват сессией:** `cowork_task new` → файл напрямую → watcher → доска. Дека узнаёт о карточке ровно так же, как о созданной руками.

**▶ Запуск:** карточка → `taskPrompt` → старт сессии в воркспейсе из `project:`. Связка `task_id → session_id` пишется на запись сессии.

**«В работе»:** карточка считается в работе, если жива сессия, запущенная из неё, и она в состоянии `работает` или `ждёт ввода`. Перезапуск тайла (⟳) тащит связку за собой, потому что она на записи сессии.

**Закрытие:** ✓ на доске или `cowork_task done <id>` → `status: done` + `resolved:` → watcher → карточка уезжает в колонку done. Колонка done показывает последние 20 по `resolved`, с «показать все».

## Ошибки и деградация

Принцип тот же, что у вас с хуками: сломался вспомогательный механизм — фича теряет удобство, а не работоспособность.

| Что сломалось | Поведение |
|---|---|
| Watcher не поднялся (сетевой FS, волт в облачной папке, лимит inotify) | Fallback на опрос раз в 5 с + принудительный рефреш при переключении на вид «Доска». Теряется мгновенность, не функциональность |
| Внешний корень не существует / нет прав | Доска показывает путь и конкретную причину + «настроить». Каталоги по произвольному пути **не создаём молча**; `.cowork/tasks/` при `kind: project` создаём сами при первой карточке |
| `cowork_task` запущен без env (вне деки) | Внятная ошибка в stderr, exit ≠ 0, ничего не пишет. Агент увидит и не будет угадывать путь |
| Файл без `id` в frontmatter | Не карточка. Игнорируется молча — это условие сосуществования с волтом |
| `id` есть, но frontmatter битый | Карточка показана в состоянии «повреждена» с путём; файл **не** трогаем. Молчать нельзя: незаметно исчезнувшая задача — худший баг трекера |
| Дубликаты `id` (заметку скопировали) | Обе карточки видны и помечены конфликтом; `resolve` по такому `id` отказывается работать вместо записи в случайную из двух |
| ▶ на карточке с `project:`, которого нет среди воркспейсов | Не запускаем, говорим прямо. Подставить активный воркспейс значило бы уронить работу в чужой каталог |
| По карточке уже есть живая сессия | Вторую не поднимаем, фокусируем существующую — как scheduled-сценарий пропускает запуск, если предыдущий ещё работает |
| Воркспейс без `tracker` в конфиге | Пустое состояние с «настроить». Не ошибка |

## Тестирование

Логика уезжает в чистые функции, тонкие слои остаются непокрытыми намеренно — как `resolveScheduledWorkspace` и `placeholders.ts` сейчас.

**Rust (`cargo test`)**
- `frontmatter`: валидный; без `id`; с `id` и битым полем; сериализация round-trip.
- `FsTaskProvider` на tempdir: `create → list → resolve`; поиск по `id` после переименования файла; запись через temp+rename не оставляет частичных файлов; скан не рекурсивный и не считает карточками посторонние заметки; дубликаты `id` дают конфликт, а не случайный выбор.
- Фильтр по `project:` на общем корне.
- Дебаунс событий — чистая функция от списка событий, как существующий `next_backoff`.
- `cowork_task` без обязательных env — exit ≠ 0 и ни одного записанного файла.

**TS (`vitest`)**
- `taskPrompt(task)` — форма промпта, включая карточку без тела.
- `derivedStatus(task, sessions)` — главный тест фичи: живая сессия, мёртвая, несколько, перезапущенная, чужая.
- Фильтрация и сортировка доски; счётчик открытых в сайдбаре; колонка done с ограничением в 20.

**Ручной чек (автотестом не покрыть):** направить корень в настоящий Obsidian-волт с сотней заметок и убедиться, что карточками стали только карточки, а доска не показала сотню повреждённых.
