# cowork-deck — устройство приложения

Дата: 2026-07-22
Статус: согласовано, готово к плану реализации

## Назначение

Настольное приложение для одновременной работы с несколькими сессиями Claude Code
на одном экране. Личный инструмент (один пользователь). Три опорные возможности:

1. Несколько живых терминалов Claude Code в одном окне (плитки).
2. Уведомления о состоянии каждой сессии: работает / ждёт ввода / закончил / ошибка.
3. Сценарии по кнопке («коворк-навыки») — сохранённый текст задания, который по нажатию
   открывает новую панель-терминал в нужной папке проекта и отдаёт этот текст первым
   сообщением в `claude`.

## Сквозные требования

- Минимальный расход ресурсов ПК (ключевое требование → выбрана основа Tauri).
- Кросс-платформенность: Windows / macOS / Linux.
- Рабочие пространства по проектам.

## Основа

- **Tauri** (ядро на Rust + системный просмотрщик страниц для интерфейса).
  Выбран за минимальный расход памяти (цель — < 100 МБ в покое) и системный
  просмотрщик вместо вложенного браузера.
- Интерфейс — веб-страница (xterm.js для терминалов) внутри окна Tauri.
- Обмен между ядром и интерфейсом — встроенные вызовы и события Tauri. Наружу в сеть
  ничего не открывается; всё локально.

## Компоненты

### Ядро (Rust)

- **Менеджер псевдотерминалов** — на каждую панель запускает отдельный процесс `claude`
  в псевдотерминале (библиотека portable-pty). Рабочая папка = путь выбранного
  рабочего пространства. Байты потоком идут в интерфейс и обратно. При закрытии окна
  все процессы аккуратно завершаются.
- **Локальный слушатель состояния** — крошечный слушатель на 127.0.0.1 на случайном
  свободном порту. Принимает события от перехватчиков Claude Code. Каждой сессии выдаётся
  уникальный опознавательный ключ, чтобы связать событие с нужной панелью.
- **Внедрение перехватчиков** — при запуске сессии ядро формирует временный файл настроек
  Claude Code с перехватчиками на события (ждёт ввода/разрешения, закончил ответ,
  завершение сессии) и запускает `claude` с этим файлом. Перехватчик при событии стучится
  на локальный слушатель.
- **Хранилище настроек** — локальные файлы (TOML/JSON) в папке настроек приложения:
  рабочие пространства и сценарии.

### Интерфейс (страница в окне)

- Слева: переключатель рабочих пространств и список сессий с цветными метками состояния.
- В центре: плитки терминалов (xterm.js), с изменяемым размером.
- Сверху/сбоку: кнопки сценариев (общие + принадлежащие текущему пространству).

## Модель данных

- **Рабочее пространство**: `{ id, имя, путь_к_папке, цвет }`
- **Сценарий**: `{ id, имя, значок, текст_задания, привязка_к_пространству | общий }`
- **Сессия** (только во время работы): `{ id, id_пространства, id_сценария?, дескриптор_псевдотерминала, состояние }`

## Определение состояния

Основной способ — встроенные перехватчики Claude Code (не разбор текста на экране):

| Событие перехватчика                 | Состояние панели | Уведомление ОС |
|--------------------------------------|------------------|----------------|
| нужен ввод / разрешение / простой     | ждёт ввода       | да             |
| ответ завершён                        | закончил         | да             |
| задание запущено / идёт работа        | работает         | нет            |
| ненулевой выход процесса / сбой        | ошибка           | да             |

Системные уведомления шлются только на переходах в «ждёт ввода / закончил / ошибка».

**Запасной вариант:** если перехватчики по какой-то системе не заведутся, панель всё равно
работает как обычный терминал — просто без цветной метки. Точный механизм подсовывания
настроек проверяется на этапе плана реализации (единственное место с небольшой неизвестностью).

## Обработка ошибок

- `claude` не найден → понятное сообщение + поле для указания пути к исполняемому файлу.
- Процесс упал → метка «ошибка», накопленный вывод сохраняется, кнопка «перезапустить».
- Слушатель недоступен / порт занят → берётся другой свободный порт; если совсем никак —
  работа без меток, окно не падает (мягкая деградация).

## Проверка (тесты)

- Модульные тесты Rust: хранилище настроек; создание/правка сценариев и рабочих пространств;
  перевод событий перехватчиков в состояния панели.
- Интеграционный тест псевдотерминала на фальшивой команде, которая эмулирует вызовы
  перехватчика (без запуска настоящего `claude`).
- Интерфейс — лёгкие проверки компонентов + ручной прогон.

## Границы (сознательно не делаем)

- Нет фоновых сессий: сессии завершаются вместе с окном.
- Нет облака и синхронизации.
- Нет удалённого доступа.
- Один пользователь.
