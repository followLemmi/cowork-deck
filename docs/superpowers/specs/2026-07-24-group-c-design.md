# cowork-deck — «Наблюдаемость и отличия» (Группа C) — Design Spec

**Дата:** 2026-07-24
**Ветка:** feat/group-c (от `main`, merge Группы B = `6dd04f1`)
**Контекст:** третий пул из roadmap (см. vault `Overview/cowork-deck - Roadmap (Next Pool)`). Release 1.0 + Группа A + Группа B влиты в `main`. Группа B дала детерминированный `--session-id` — это ключ к поиску transcript claude для подсчёта токенов.

## Цель
Наблюдаемость и отличительные фичи: расход токенов на сессию/проект, git-контекст на плитке, восстановление размера/позиции окна и активного пространства, и плавающая пилюля «N ждут ввода» поверх всех окон.

## Границы (scope)
**Входит:** 4 фичи Группы C — (1) персист окна/пространства, (2) git-индикатор на плитке, (3) токены на плитке + сводка, (4) пилюля статуса поверх окон.
**НЕ входит:** стоимость в $ (только токены; цену можно добавить позже), крупные ставки (мультипровайдер, agent teams, browser automation, mobile, project memory, SSH, tunnel).

## Глобальные ограничения (наследуются всеми задачами)
- Tauri v2, ядро Rust + ванильный TypeScript + xterm.js. Только ванильный TS, без фреймворков.
- Целевой расход памяти < 100 МБ; только лёгкие зависимости.
- Тёмная тема, палитра One Dark, дизайн-токены из `styles.css` (`:root`).
- **Анимации только на `transform`/`opacity`; НИКОГДА не анимировать `box-shadow`/`filter` с `infinite` (ADR-008 — вызывало системный лаг через WebKit-repaint).**
- Строки интерфейса — на русском, в существующем стиле.
- Команды тестов неизменны: `npm test` (vitest run), `cargo test --manifest-path src-tauri/Cargo.toml`. Не ломать существующие тесты (64 vitest / 17 cargo на старте ветки). `tsc --noEmit` чист.
- Коммиты — Conventional Commits.

## Новые зависимости
- `tauri-plugin-window-state` (Cargo) + `@tauri-apps/plugin-window-state` (JS) — авто-персист размера/позиции окна. Регистрация плагина в `main.rs`; разрешение в `capabilities/default.json`. **⚠️ Требует пересборки Rust.**

## Проверенные факты (спайк)
- Transcript claude: `~/.claude/projects/<encoded-cwd>/<session-id>.jsonl`. Имя файла = session-id, который мы сами задаём (`--session-id`, Группа B). **Поиск по glob `~/.claude/projects/*/<session-id>.jsonl`** — не нужно воспроизводить кодировку cwd (там `/` и `.` → `-`).
- Каждая строка ассистента несёт `usage`: `input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`. Токены точные; стоимость не считаем.

## Фича 1 — Персист окна/пространства

**Поведение**
- Приложение запоминает размер и позицию окна между запусками; при старте — восстанавливает.
- Запоминает активное пространство; при старте выбирает его (если существует).

**Архитектура**
- **Окно:** плагин `tauri-plugin-window-state`. Регистрация `.plugin(tauri_plugin_window_state::Builder::default().build())` в `main.rs`; JS-обёртка не нужна (плагин сам сохраняет по событиям окна). Capability: `window-state:default`.
- **Активное пространство:** новый файл `ui_state.json` в `app_config_dir`. Тип `UiState { active_workspace_id: Option<String> }` (serde rename `activeWorkspaceId`). Методы `Store::ui_state()`/`save_ui_state()`; команды `load_ui_state`/`save_ui_state` (+регистрация в `main.rs`).
- Frontend (`src/workspaces.ts`): при выборе пространства → `saveUiState({ activeWorkspaceId })`; в `load()` после загрузки — если сохранённый id есть и присутствует в списке, выбрать его (иначе поведение как сейчас). IPC-обёртки `loadUiState`/`saveUiState` + тип `UiState` в `src/ipc.ts`.

**Тесты:** cargo — round-trip `ui_state`/`save_ui_state` (+ пустой/NotFound). vitest — `workspaces.load()` выбирает сохранённый id при наличии, иначе дефолт (мок ipc).

## Фича 2 — Git-индикатор на плитке

**Поведение**
- В шапке плитки — ветка + признак «грязного» дерева для папки воркспейса. Не git-репо → индикатор скрыт.

**Архитектура**
- **Backend:** команда `git_status(cwd: String) -> GitStatus` где `GitStatus { branch: Option<String>, dirty: bool }`.
  - branch: `git -C <cwd> rev-parse --abbrev-ref HEAD` (trim; при ошибке/не-репо → None).
  - dirty: `git -C <cwd> status --porcelain` непустой вывод → true.
  - Регистрация в `main.rs`. IPC-обёртка `gitStatus(cwd)` + тип `GitStatus` в `src/ipc.ts`.
- **Frontend:** бейдж в `tile-head` (напр. `⎇ main` + `•` при dirty; скрыт при `branch===null`). Обновляется поллингом (см. cross-cutting). Дедуп: за один тик запрашивать `git_status` уникально по cwd (несколько плиток одной папки → один вызов), результат раскладывать по плиткам.

**Тесты:** cargo — `git_status` на временном git-репо (создать репо, проверить branch + dirty после изменения файла); не-репо → None. vitest — чистая ф-я дедупа: список плиток → уникальные cwd для запроса + разложение результата обратно по сессиям.

## Фича 3 — Токены на плитке + сводка

**Поведение**
- На плитке — компактный счётчик billable-токенов `↑{in} ↓{out}` (cache-токены — в тултипе). Обновляется поллингом.
- В сайдбаре — сводка: сумма in/out по всем открытым сессиям.

**Архитектура**
- **Backend:** команда `session_tokens(session_id: String) -> TokenUsage` где `TokenUsage { input: u64, output: u64, cache_creation: u64, cache_read: u64 }`.
  - Найти transcript: glob `~/.claude/projects/*/<session_id>.jsonl` (первое совпадение). Нет файла → все нули.
  - Прочитать построчно; для каждой строки, где есть `message.usage` (ассистентские), прибавить поля. (Толерантно к строкам без usage / не-JSON.)
  - Регистрация в `main.rs`. IPC `sessionTokens(sessionId)` + тип `TokenUsage` в `src/ipc.ts`.
- **Frontend:** формат-хелпер `formatTokens(n)` (напр. `1234 → "1.2k"`); бейдж в `tile-head`; сводка в сайдбаре (в `Deck.renderList` или отдельным элементом). Чистые функции суммирования/форматирования — тестируемы.

**Тесты:** cargo — суммирование usage из JSONL-фикстуры (несколько строк, включая строку без usage и мусорную) → корректные суммы; отсутствующий файл → нули. vitest — `formatTokens` (сотни/тысячи/миллионы, границы); суммирование по сессиям для сайдбар-сводки (чистая ф-я).

## Фича 4 — Пилюля статуса поверх окон

**Поведение**
- Плавающая пилюля «N ждут ввода» поверх всех приложений; видна только при N>0, прячется при N=0.
- Клик по пилюле → поднять главное окно и сфокусировать следующую ждущую сессию (переиспользует `focusNextWaiting`).

**Архитектура**
- **Спайк ПЕРЕД реализацией (первая задача фичи):** создать второе окно Tauri — маленькое, `transparent: true`, `always_on_top: true`, `decorations: false`, `skip_taskbar: true` — и подтвердить, что оно рисуется поверх других приложений на macOS (проверить `macOSPrivateApi`/`transparent` в конфиге). Если прозрачность капризит — fallback: непрозрачная мини-пилюля с тёмным фоном (без transparent).
- **Окно:** второй `WebviewWindow` с `pill.html` (+ `src/pill.ts`), создаётся при старте скрытым. Позиция — верхний-правый угол по умолчанию, перетаскивание через `data-tauri-drag-region`.
- **Связь:** waiting-count вычисляется в `Deck.setState`/`renderList` (событийно, НЕ поллинг). Main эмитит событие `pill://count` с N при изменении. `pill.ts` слушает: N>0 → `show()` + текст «N ждут ввода», N==0 → `hide()`. Клик по пилюле → `emit("pill://focus-next")`; main слушает → `raise/focus` окна + `deck.focusNextWaiting()`.
- Регистрация окна и capability для метки окна пилюли (сверить строки в `src-tauri/gen/schemas/`).

**Тесты:** vitest — чистая ф-я `pillLabel(n)` («1 ждёт ввода»/«N ждут ввода», плюрализация как `waitingVerb`); show/hide маппинг по N. Живое поведение окна — ручная приёмка на десктопе.

## Cross-cutting

- **Поллинг:** один `setInterval` (интервал 5с) в `Deck` (или `main.ts`): за тик — `git_status` (уникально по cwd) + `session_tokens` по каждой плитке → обновляет бейджи плиток и сайдбар-сводку. Запускать при появлении первой плитки, останавливать когда плиток нет. Обновления — только текст бейджей (дешёвые DOM-правки; никаких бесконечных анимаций — ADR-008).
- **Реестр команд:** если добавляются пользовательские команды/хоткеи (напр. toggle пилюли не нужен — она авто), регистрировать в `src/commands.ts` + `src/palette.ts` + `src/main.ts`.
- **Уроки прошлых сессий:** `vi.hoisted()` для мок-переменных; `// @vitest-environment jsdom` для тестов, тянущих xterm/DOM; capability-строки сверять в `gen/schemas/`; хоткеи через `matchHotkey(e, isMac)`.
- **Порядок реализации:** 1) персист окна/пространства → 2) git-индикатор → 3) токены → 4) пилюля (спайк transparent-окна первым шагом фичи). Каждая задача — per-task ревью; в конце — whole-branch ревью (opus).

## Критерии готовности
- Размер/позиция окна и активное пространство восстанавливаются после перезапуска.
- На плитке видны ветка+dirty (для git-репо) и счётчик токенов, обновляются поллингом.
- Сайдбар показывает суммарные токены по открытым сессиям.
- Пилюля появляется поверх окон при N>0 ждущих, клик поднимает окно и фокусирует следующую ждущую; при N=0 скрыта.
- `npm test` и `cargo test` зелёные; `tsc` чист; новая зависимость только `tauri-plugin-window-state`.
