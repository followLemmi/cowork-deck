# cowork-deck — «Ввод и управление» (Группа A) — Design Spec

**Дата:** 2026-07-23
**Ветка:** feat/release-1.0 (продолжение работ над следующим пулом)
**Контекст:** первый спек из «следующего пула» (12 фич), см. vault `Overview/cowork-deck - Roadmap (Next Pool)` и `Research/AgentsRoom - competitive analysis`. Release 1.0 (P0 + слой внимания + дизайн-система) реализован; поверх добавлены собственные модалки (`src/modal.ts`), т.к. webview Tauri не поддерживает `window.prompt()`.

## Цель
Довести взаимодействие с приложением: нормальный ввод данных (нативный выбор папки + редактирование), клавиатурное управление (хоткеи + лёгкая палитра), поиск/очистка в терминале и замыкание петли уведомлений (клик → фокус нужной сессии).

## Границы (scope)
**Входит:** 4 фичи Группы A. **НЕ входит** (последующие спеки пула): пилюля статуса поверх окон, токен-метр + статистика, git-индикатор на плитке, persist окна/пространства, `claude --continue`, плейсхолдеры сценариев, restore session, broadcast-ввод.

## Глобальные ограничения (наследуются всеми задачами)
- Tauri v2, ядро Rust + ванильный TypeScript + xterm.js. **Только ванильный TS, без фреймворков.**
- Целевой расход памяти < 100 МБ; только лёгкие зависимости.
- Тёмная тема, палитра One Dark, дизайн-токены из `styles.css` (`:root`). Анимации только на transform/opacity/box-shadow; `prefers-reduced-motion` уже обработан глобально.
- Строки интерфейса — на русском, в существующем стиле.
- Команды тестов неизменны: `npm test` (vitest), `cargo test --manifest-path src-tauri/Cargo.toml`. Не ломать существующие тесты.
- Коммиты — Conventional Commits.

## Новые зависимости
- `@tauri-apps/plugin-dialog` (JS) + `tauri-plugin-dialog` (Cargo) — нативный выбор папки. Требует регистрации плагина в `src-tauri/src/main.rs` и разрешения `dialog:default` в `src-tauri/capabilities/default.json`. **⚠️ Требует пересборки Rust (перезапуск `tauri dev`).**
- `@xterm/addon-search` (JS) — поиск в терминале.

## Фича 1 — Нативный выбор папки + формы создания/редактирования

**Поведение**
- Создание/редактирование пространства и сценария — через модальные **формы** (не пошаговые `promptModal`).
- Форма пространства: `имя` (текст) · `путь` (readonly-текст + кнопка «Выбрать папку…» → `open({ directory: true })`) · `цвет` (набор пресетов-точек).
- Форма сценария: `имя` (текст) · `эмодзи` (текст, дефолт «▶») · `промпт` (**textarea**, многострочный) · `область видимости` (переключатель: текущее пространство / общий).
- Редактирование: иконка-карандаш ✎ на строке при hover (рядом с ✕) → та же форма, поля предзаполнены текущими значениями.

**Архитектура**
- Две целевые функции-формы (без обобщённого движка полей — YAGNI). Разместить в `src/forms.ts`, переиспользуя оверлей/стили из `src/modal.ts`:
  - `workspaceForm(initial?: {name; path; color}): Promise<{name; path; color} | null>`
  - `skillForm(initial?: {name; icon; prompt; workspaceId}, activeWorkspaceId): Promise<{name; icon; prompt; workspaceId} | null>`
- `src/dialog.ts` — тонкая обёртка `pickFolder(): Promise<string | null>` над `@tauri-apps/plugin-dialog` `open({ directory: true })` (изолирует зависимость, легко мокается в тестах).
- `workspaces.ts`: `add()` и новый `edit(id)` вызывают `workspaceForm`; сохранение через существующий `saveWorkspace` (upsert по id). ✎ в `render()`.
- `skills.ts`: `add()` и новый `edit(id)` вызывают `skillForm`; сохранение через `saveSkill` (upsert). ✎ в `render()`.
- Rust `save_workspace`/`save_skill` уже upsert по id — изменений не требуют.

**Тесты (jsdom):** формы возвращают собранные значения на OK и `null` на отмену; предзаполнение при редактировании; `pickFolder` замокан. Нативный диалог — ручная проверка на десктопе.

## Фича 2 — Хоткеи + лёгкая командная палитра

**Поведение**
- Карта хоткеев (подтверждена): `Cmd/Ctrl+K` — палитра · `Cmd/Ctrl+1..9` — фокус плитки N · `Cmd/Ctrl+Shift+]` — прыжок к следующей сессии в состоянии «ждёт ввода» · `Cmd/Ctrl+N` — новая сессия (в активном пространстве) · `Cmd/Ctrl+W` — закрыть активную (с подтверждением, если состояние working/waitingInput) · `Cmd/Ctrl+F` — поиск в активном терминале.
- Палитра (`Cmd/Ctrl+K`): модалка с полем фильтра + список команд; навигация стрелками, Enter — выполнить, Esc — закрыть.

**Архитектура**
- `src/commands.ts` — реестр команд: массив `{ id: string; title: string; run: () => void; hotkey?: string }`. Единый источник и для хоткеев, и для палитры (DRY).
- Чистая функция `matchHotkey(event) => commandId | null` (тестируется без DOM).
- Чистая функция выбора следующей ждущей: `nextWaitingIndex(states: SessionState[], current: number) => number | null` (тестируется отдельно).
- Глобальный слушатель `keydown` на `window`; в терминале — `term.attachCustomKeyEventHandler(e => …)` возвращает `false` для наших Cmd/Ctrl-комбо, чтобы xterm их не поглощал (обычный ввод не трогаем).
- `src/palette.ts` — модалка палитры поверх оверлея из `modal.ts`.
- `Deck` предоставляет методы, вызываемые командами: `focusByIndex(n)`, `focusNextWaiting()`, `closeActive()`, геттер активной сессии, `searchActive()`, `clearActive()`.

**Тесты (jsdom + чистые функции):** `matchHotkey` (комбо → id), `nextWaitingIndex` (несколько сессий, обход по кругу, нет ждущих → null), палитра (фильтрация списка, Enter вызывает `run`).

## Фича 3 — Поиск / очистка терминала

**Поведение**
- `Cmd/Ctrl+F` в активной плитке открывает инлайн-бар поиска сверху плитки: поле ввода, next/prev, Esc — закрыть.
- Очистка scrollback: команда в палитре + маленькая кнопка в шапке плитки. (`Ctrl+L` в самом шелле продолжает работать штатно.)

**Архитектура**
- `TerminalPanel` загружает `SearchAddon` из `@xterm/addon-search`; методы `search(term)`, `findNext()`, `findPrevious()`, `clear()` (обёртка `term.clear()`).
- Бар поиска — DOM-элемент внутри плитки (в `sessions.ts` при создании плитки), скрыт по умолчанию; управляется из команды/хоткея.

**Тесты:** обёртки `TerminalPanel.search/clear` вызывают методы аддона (лёгкий jsdom-тест с моком аддона). Визуальная проверка бара — ручная.

## Фича 4 — Клик уведомления → фокус

**Поведение**
- Клик по OS-уведомлению о переходе сессии в waitingInput/error/ended поднимает окно приложения на передний план и фокусирует именно ту плитку.
- Linux: мягкая деградация — как минимум поднять окно и сфокусировать последнюю ждущую сессию.

**Архитектура**
- При отправке уведомления (`sessions.ts` `setState`) присваивать ему числовой `id` и вести `Map<number, sessionId>`.
- Зарегистрировать обработчик `onAction` (`@tauri-apps/plugin-notification`); по срабатыванию: `getCurrentWindow().setFocus()` (+ `show()`/`unminimize()` при необходимости) → `deck.focusTile(sessionId)` по карте.
- Изолировать в тонкой обёртке (напр. `src/notify.ts`), чтобы `Deck` не зависел напрямую от plugin-API и это мокалось.
- Возможные доп. разрешения capability для управления окном (`core:window:allow-set-focus` и т.п.) — уточнить при реализации.

**Тесты:** маппинг notifId→session и выбор плитки — чистая логика (jsdom/unit). Реальный клик уведомления, фокус окна — ручная проверка на десктопе (в чек-лист).

## Стратегия тестирования (сводно)
- Юнит/jsdom: формы, `matchHotkey`, `nextWaitingIndex`, фильтр палитры, обёртки поиска/очистки, маппинг уведомлений. Существующие наборы (`ipc`, `sessions`, `sessions-util`, `modal`) не ломать.
- Ручная приёмка на десктопе (в новый раздел RELEASE-чеклиста): нативный folder picker; реальные хоткеи в живом терминале (не воруются xterm); бар поиска; клик уведомления → фокус на macOS/Windows (Linux — деградация).

## Открытые вопросы к реализации (не блокеры дизайна)
- Точный набор capability-разрешений для `setFocus`/`show` под Tauri v2 — уточнить при задаче Ф4.
- Формат хранения цвета-пресета пространства (оставляем строку hex, как сейчас).
